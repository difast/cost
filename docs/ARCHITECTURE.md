# Архитектура

## Слои

```
src/core/            Чистое ядро без БД и сети — детерминированно и покрыто тестами
  calc/              Расчёт сравнительного подхода (decimal.js, округление на каждом шаге)
  adjustments/       Предложение корректировок по редакции справочника
  checks/            Автоматический контроль согласованности (ошибки блокируют отчёт)
  egrn/              Разбор XML-выписки ЕГРН, загруженной пользователем
  import/            Импорт аналогов из CSV
  report/            Шаблон → модель документа → рендеры DOCX / PDF
  snapshot.ts        Снимок оценки — единый вход для расчёта, проверок и отчёта
src/server/          Доступ к БД, авторизация, сервисы, аудит, интеграции
  integrations/      Абстракции источников данных и реестр адаптеров
src/app/api/         REST API (используется веб-клиентом и будущим Android-приложением)
src/app/app/         Интерфейс рабочего места
src/components/      Клиентские компоненты
```

## Сущности (prisma/schema.prisma)

| Сущность | Назначение |

| Adjustment | Корректировка аналога: предложено / применено / обоснование / снимок правила |

## Расчёт (src/core/calc/engine.ts)

1. Цена за м² = цена / площадь (до копеек).
2. Корректировки упорядочиваются: 1-я группа (торг, права, условия рынка), затем 2-я.
   - `sequential`: каждая применяется к результату предыдущей: `P × (1 + k)`.
   - `staged`: 1-я группа последовательно, 2-я — от базы после 1-й группы, суммой.
   Каждый шаг округляется до копеек; `после = до + Δ` — цепочка проверяется вручную.
3. Веса: равные, `1/(1+Σ|k|)`, `(S − sᵢ)/((n−1)S)` или ручные. Округление весов — методом наибольшего
   остатка, сумма ровно 1. Ручные веса не нормализуются скрыто: сумма ≠ 1 — ошибка.
4. Вклад аналога = скорр. цена × вес (до копеек); средневзвешенная цена = Σ вкладов.
5. Стоимость = средневзвешенная цена × площадь → округление до шага → цена за м² = итог / площадь.
6. Статистика: min, max, среднее, медиана, диапазон, σ, коэффициент вариации.

## Воспроизводимость

- Значения корректировок копируются в `Adjustment` вместе со снимком правила (`ruleSnapshot`: справочник, редакция, коэффициенты категорий).
- Редакцию справочника, использованную в зафиксированном расчёте, изменить нельзя — только создать новую.
- `CalculationVersion.snapshot` хранит полный снимок оценки (задание, объект, оценщик, аналоги, корректировки,
  справочник, вложения), `result` — результат, `inputHash` — хэш входа, `engineVersion` — версию ядра.
- Повторное формирование отчёта по версии пересчитывает снимок и сверяет с сохранённым результатом.
- Файл, попавший в зафиксированную версию, удалить нельзя.

## Проверки (src/core/checks)

Ошибки блокируют отчёт, предупреждения — нет. Среди проверок: обязательные поля задания/объекта/оценщика;
формат и совпадение кадастрового номера, площади, этажа, адреса с выпиской ЕГРН; согласованность дат
(оценки, осмотра, отчёта, предложений аналогов); сроки аттестата и полисов; источник, дата, адрес, скриншот
каждого аналога; дубликаты; ручные корректировки без обоснования; выход за диапазон справочника; смешение
редакций; чужие кадастровые номера, даты оценки и площади в свободном тексте (остатки другого отчёта);
сходимость цепочки корректировок, весов, итога = цена за м² × площадь; совпадение сохранённого результата с пересчётом.

## Интеграции (src/server/integrations)

Ядро не знает о поставщиках. Источник подключается адаптером с явно указанным каналом доступа:
`official_api` / `partner_api` / `licensed_data` / `user_import` / `manual`. Интерфейсы:
`PropertyProvider` (объект/здание), `ComparablesProvider` (аналоги). Сейчас работают ручной ввод,
загрузка XML-выписки ЕГРН и импорт CSV. ЦИАН, Авито, Домклик, НСПД, ГИС ЖКХ, ФИАС/ГАР, картографические
сервисы — только через официальный/партнёрский API или лицензированного поставщика. Парсинг сайтов не используется.

## Отчёты

`ReportTemplate.definition` — JSON: разделы из текстовых блоков с подстановками `{{a.valuationDate|date}}`
и встроенных блоков (`comparablesTable`, `adjustmentsTable`, `calculationChain`, `weightsTable`, …).
Все разделы строятся из одного снимка и одного результата — расхождения дат, номеров и сумм между
разделами исключены конструктивно. Новые типы отчётов — новые шаблоны без изменения рендеров.

## Модуль «Аналоги» (поиск, сравнение, корректировки)

```
Объект оценки → Metrapi (/v1/items) → нормализация в Listing → фильтры сервиса (радиус, ₽/м², мебель)
  → результаты поиска (ListingSearch, кэш 6 ч) → «Использовать» / «На проверку» → Comparable (снимок)
  → сравнение с объектом (core/comparables/compare.ts) → корректировки по справочнику (core/adjustments)
  → проверка оценщиком (ручное значение + обоснование, «Не требуется») → цепочка цены (core/calc/engine)
  → выбор аналогов (статус use) → расчёт → проверки → отчёт
```

- **Metrapi** (`src/core/listings/metrapi.ts` — контракт и нормализация, `src/server/integrations/metrapi.ts` — HTTP):
  `GET /v1/items`, `GET /v1/item/{source}/{source_id}`, `GET /v1/sources`; ключ `X-Api-Key` из `METRAPI_API_KEY`
  только на сервере; очередь запросов не чаще 1 в 2 с; при 429 too_soon — ожидание `retry_after` из тела и один
  повтор; таймаут 25 с. Фильтра по координатам в API нет — радиус считается по `lat/lon` объявлений на сервере.
  Поля, которых нет в ответе, остаются `null` («Нет данных»): мебель — только если указана в `amenities`,
  материал стен — из `house_type`, отделка — из `renovation` (исходные значения сохраняются).
- **Снимок аналога**: `Comparable.rawData` (ответ API как есть) и `normalized` (на момент включения), источник
  каждого поля — `provenance`. Повторный запрос к API оценку не меняет; «Сверить с источником» только показывает
  различия.
- **Статус аналога**: `use` (в расчёте) / `review` (на проверке) / `exclude`; `included = status === "use"`.
- **Карта** (`EnvironmentMap`): Яндекс Карты JS API 2.1 с кластеризацией; ключ выдаётся только авторизованным
  (`/api/maps/config`, `YANDEX_MAPS_JS_API_KEY` или `YANDEX_API_KEY`, ограничьте по HTTP Referer). Без ключа —
  схема по тем же координатам. Повторного геокодирования нет.

## Справочник корректировок

Фактор: тип (`discount` — скидка, `category` — коэффициенты категорий, `formula` — формула, `power` — степенная,
`manual` — экспертная), признак, группа, коэффициенты/среднее, диапазон, источник (`reference`), дата актуальности,
регион, методика, комментарий. Коэффициент **K** — множитель цены аналога, корректировка = **K − 1**:
категории `K = k(объект) / k(аналог)` (аналог хуже → K > 1 → корректировка положительная), формулы — безопасный
вычислитель `src/core/adjustments/formula.ts` (например `(So / Sa)^(-0.12)`; переменные So/Sa, Fo/Fa, Ho/Ha, Ro/Ra,
Yo/Ya, Mo/Ma, Lo/La, Ko/Ka). Новые факторы добавляются в собственную редакцию без изменения кода
(`POST /api/directory/{id}/factors`). Копия демонстрационного справочника остаётся демонстрационной до явного
подтверждения значений источником.

Ручное изменение корректировки сохраняет исходное автоматическое значение (`suggestedValue`), новое значение,
автора и дату (`overriddenById`, `overriddenAt`), характеристики на момент изменения (`basisSnapshot`) и
обоснование (`comment`, обязательно). Веса — `src/core/calc/weights.ts`: одно описание формулы для интерфейса,
расчёта и отчёта.

Новые проверки: `ADJ_SIGN` (знак противоречит сравнению), `ADJ_VALUE_MISMATCH` (значение в расчёте ≠ карточке),
`ADJ_BASIS_CHANGED` (характеристики изменились после ручной правки), `ADJ_LARGE`, `ADJ_NOT_REQUIRED_NO_REASON`,
`DISPERSION_GROWTH` (разброс после корректировок вырос), `COMPARABLE_IN_REVIEW`.

## ГАР (ФИАС) и Росстат

- ГАР: `npm run gar:import -- --file … --regions 77,50|all` — ZIP64 по записям, SAX-разбор, батчи по 5000,
  только нужные поля (`GarAddrObj`, `GarHouse`, `GarHierarchy` → плоская `GarAddress` с GIN-индексом по
  нормализованному адресу). Поиск: `GET /api/address/search`, подсказки в поле «Адрес». Подробнее — `data/gar/README.md`.
- Росстат: `npm run rosstat:analyze` (потоковый анализ структуры CSV/XLSX) → маппинг → `npm run rosstat:import`
  (`RosstatSeries`, `RosstatValue`, upsert без дублей). Подробнее — `data/rosstat/README.md`.
